# Project-wide standing rules for Claude sessions

## Prelaunch data posture (set 16 Sep 2026, per Joshua, via PR #63 — until Joshua explicitly says otherwise)

Price2Book has no active contractors; Elite is inactive too. All workstreams
operate as prelaunch/test development. Existing contractor/test business data
(Elite, BrightPath, rehearsal catalogs, test bookings, saved sessions) may be
discarded and rebuilt for a fresh launch, within a task's authorized scope.
Do not require preservation or migration of hypothetical active customers or
disposable test history. Prefer fresh initialization and focused correctness
checks; defer existing-customer-only adoption hardening. Do not ask again
whether Elite/rehearsal data must be retained.

This does NOT authorize:
- discarding source/canonical definitions, other workstreams' parallel work,
  owner access, or credentials
- treating "test mode" as sandboxing external integrations, or as
  authorization for unrelated deployments or messages
- skipping real pricing/security correctness or any task's explicit
  boundaries — this rule is about data retention, not correctness
- any production/Neon write, merge, deployment, or live reset — those still
  require their own explicit, in-conversation authorization every time
