  WHAT THIS ESTABLISHES
    Promotion moves the production target AND every generated alias mapping

    verifyHosts checking each host separately is still what would DETECT one,
    and proof 4 case 1 showed a partial state is reachable by other means.

  A PREDICTION OF MINE, REFUTED
    In proof6-blocked.txt I wrote that access state looked like "the host
    serving the current production target is public, the others are protected",
    and predicted it would INVERT after promotion.

    IT DID NOT INVERT. Every host's access state was unchanged, while the
    deployment it pointed at changed. So protection is not a function of whether

    the shortest project alias stayed public throughout. Protection tracks the
    KIND of generated host, not what it points at.

    I inferred a rule from one correlated observation and stated a prediction
    from it. The experiment refuted it, which is the only reason it is known.
