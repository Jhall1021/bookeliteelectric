READING OF THESE RESULTS

  Repository        Price2Book/p2b-release-proofs
  Numeric id        1357368650
  Private           yes
  Default branch    main (configured; NO commits yet, so the ref does not exist)

  The numeric id is what gitSource identifies a repository by, so 1357368650 is
  the value the disposable Vercel project's creation calls will carry. It is
  unrelated to CANONICAL.repoId, which remains 0 and is a separate task.

  409, NOT 404, ON THE REF. I predicted a 404 for git/ref/heads/main; GitHub
  answers 409 "Git Repository is empty" for the ref and 404 for the contents
  path. Both are the repository's state rather than a token problem, but the
  guard's fresh-main read uses `curl -f`, which treats any non-2xx as failure —
  so against the repository as it stands the guard would refuse MAIN_UNREADABLE
  and fail closed. That is correct behaviour, and it resolves once main exists.

  THE `permissions` FIELD IS NOT EVIDENCE OF TOKEN SCOPE. It reports the
  ACCOUNT's permissions on the repository — admin/push/pull are all true because
  the account owns it — and says nothing about what this token may do. The 403s
  in check 4 are the actual evidence: three endpoints whose scopes were left at
  No access all refuse with "Resource not accessible by personal access token",
  while Contents-backed reads succeed. The token is narrower than the account.

  An earlier probe of /collaborators returned 200 and was DISCARDED rather than
  reported: that endpoint can answer 200 on a repository the account owns, so it
  measured ownership, not the grant.

  Read-only throughout. Nothing was created, updated, deleted or pushed.

WHAT THE 403s DO AND DO NOT ESTABLISH

  The three refusals establish that Secrets, Webhooks and Variables are denied.
  They do NOT enumerate the grant: they are three probes, not a survey, and a
  permission not probed is simply unmeasured. The positive claim they support is
  narrow — this token is not a full-account token — and nothing broader.

  Content access is established separately, and positively: reading the uploaded
  guard out of the PRIVATE repository is itself the proof that the Contents read
  the build needs actually works. Until something is uploaded, checks 2 and 3
  answer 409/404 for lack of content, which demonstrates reachability but not
  readability.
