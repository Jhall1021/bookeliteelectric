  rootDirectory IS ABSENT, NOT NULL — and it does not matter here

    The response omits the field rather than returning null. A comparison that
    distinguished absent from null would report drift on a correct deployment.
    liveIO's settings() maps `o.rootDirectory ?? null`, so absence becomes null
    and compareBuild sees a match. The normalisation is load-bearing, and it is
    working. Worth knowing that it is the only thing standing between an absent
    field and a false drift refusal.

    WHAT THIS DOES NOT ESTABLISH. It is not proof 4's negative case. Proof 4
    requires the GUARD to run and refuse; here the guard was never fetched, so
    nothing was decided by it. A build that fails before the guard is not a
    guard refusal, and recording it as one would be exactly the confusion these
    proofs exist to avoid.

    WHAT IT DOES INCIDENTALLY CORROBORATE. The chain fails CLOSED. An
    unreachable guard stopped the build rather than falling through to
    npm run build — which is what `curl -f`, the non-empty test and `&&` are
    there for. Recorded as corroboration of a design property, not as a proof.
